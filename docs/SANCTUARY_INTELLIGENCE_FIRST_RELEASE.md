# Sanctuary Intelligence — First Release

**Status:** Feature-branch implementation; checks and browser QA pending.
**Base:** `main`
**Scope:** Private questionnaire-driven reflection and an optional, explainable learning path.

## Member experience

The existing six-prompt self-discovery flow stays opt-in, one question at a time, skippable, and editable before the member creates a reflection. The result keeps the existing answer-grounded pattern, practical action, micro-lesson, journal prompt, copy/export controls, and explicit clear-session action.

When the member answers the learning prompt, the result additionally offers a small learning path:
- A suggested approach based on the member's own selected preference (reading, watching, hands-on practice, discussion, or a mix).
- A first step and a small practice activity.
- Optional adjustments based on their stated motivation and decision-support preferences.
- A reflection question and a clear note that this is not a validated learning style, fixed personality, diagnosis, or prediction.

## Privacy and safety boundaries

- Raw answers remain in component memory for the current page session only.
- No raw answers or derived learning plan are persisted, transmitted, logged, or added to profile fields by this change.
- No new migration, database schema, RLS policy, API, provider setting, payment, or secret is introduced.
- The learning plan is generated by a deterministic local rules function; no external model or network request is used.
- Suggestions are optional, reversible, and phrased as experiments. Members can leave and clear the session.
- This does not claim that the feature is production-ready or that browser/device acceptance has passed.

## Validation plan

1. Run `npm run check:self-discovery` to check question domains, answer coverage, validation, privacy guardrails, and learning-plan coverage.
2. Run `npm run typecheck`.
3. Run `npm run build`.
4. Manually test keyboard-only navigation, skipped learning answers, each learning option, answer edits, clear-session behavior, export, and mobile layout.
5. Do not add persistent save/resume or profile sharing until the existing privacy contract, schema, RLS, consent and deletion flows have been reviewed and owner-approved.
