# Economy

The Wallet page is the first persistent economy feature. It displays the signed-in Supabase user's token balance and recent bundle purchases. Guest and local-demo accounts cannot buy tokens, and the browser never changes wallet balances. `WalletPanel` is mounted in the authenticated shell and is reachable from the Wallet navigation item.

Token bundles are configured as GBP 100/£1, 600/£5, and 1,200/£10. Checkout is created server-side by the authenticated `token-checkout` Supabase Edge Function using fixed Stripe Price IDs. Credits are granted only after a signature-verified Stripe webhook calls the service-only, idempotent database function. Bundle cards remain disabled until `TOKEN_CHECKOUT_ENABLED=true` and the expected Edge Function secrets are present.

The shareable Stripe Payment Link is not used for wallet purchases because it cannot safely associate an individual checkout with the signed-in Sanctuary account. Do not share/use that link for in-app token sales; direct purchases through it will not be credited to a wallet. In staging, enable the flag only with Stripe test keys and test Price IDs after the webhook is configured. Keep live checkout disabled until the migration, functions, mode-matched Price IDs, webhook, end-to-end test, and refund/chargeback handling policy are confirmed. The checkout function retrieves each Stripe Price and verifies it is active, one-time, the expected GBP amount, and in the configured mode before allowing checkout.

This first release has no token spending, transfers, marketplace, cash-out, VIP unlock, post promotion, cosmetics, or gifts. Those are planned extensions and must be implemented with server-side ledger transactions and clear product rules before use. The wallet and ledger are account-bound; deleting an account deletes its stored wallet history. The system currently records verified purchases only; refund/chargeback reconciliation must be added before enabling token spending or trading.

Status: the migration has not been applied and the Edge Functions have not been deployed or validated in this workspace. `TOKEN_CHECKOUT_ENABLED` defaults to `false`. Before live sales, ask the product owner how to handle full/partial refunds, disputes, manual support, and reversals when tokens have already been spent; do not guess that policy.
