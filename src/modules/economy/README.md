# Economy

Owns wallet balances, credit packages, VIP tiers, cosmetic catalog, inventory, and equipment state. `service.ts` and `useWallet.ts` provide an in-memory demo adapter and typed UI hook; `WalletPanel` exposes mock checkout, tier unlocks, and cosmetic management.

The UI's `stripe-mock` checkout never contacts Stripe or charges money, and its wallet/inventory snapshots remain browser-local and editable. The server now has a Stripe-signed Checkout fulfillment route and a Supabase migration for service-role-only, transactional, idempotent credit/VIP fulfillment. Supported Checkout sessions must include the same Supabase Auth user UUID in `client_reference_id` and `metadata.user_id`, contain exactly one quantity-one configured Stripe Price, and use one of the documented price IDs. The current app does not create real Checkout sessions or connect local demo accounts to Supabase Auth, so do not enable live payments until that cutover, production wallet reads, refund/reconciliation handling, and operational review are complete. Never trust client-supplied wallet balances or purchase permissions.
