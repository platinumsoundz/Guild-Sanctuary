# Profiles

Owns user profile presentation, rich customization, per-field privacy controls, social-link visibility, own-post/media showcase, and public profile discovery. The profile page is display-first: `ProfileDashboard` renders the profile card and the user's posts/media, and all editing is inside an “Edit profile” dialog. The dialog edits picture/banner, theme color, bio, location, age, star sign, belief, and public visibility flags. The theme picker previews the profile accent across the application; banner selection updates the profile-card preview and saves with the profile. Facebook, X/Twitter, YouTube, Xbox, PlayStation, Steam, Epic Games, and Reddit links are stored in the typed `Profile.socialLinks` contract and are returned publicly only when the social-links privacy flag is enabled. Wallets, paid top-ups, spending, and inventory are owned by `src/modules/economy/`.

When Supabase is configured, profile updates write to `profiles` and public search reads the `public_profiles` view. Discover lists all public, discovery-enabled profiles on load and filters by username/display name; it also states whether Supabase or the local demo store is active and surfaces missing-view/configuration errors. The view applies visibility, discovery, suspension, and per-field privacy rules; it never exposes email addresses. Search uses the trigram indexes added by the hardening migration. The local demo store remains a fallback when Supabase is absent.

The profile card and Discover avatar display `equippedFrame` when the user has unlocked a frame through the economy module.

Image URLs and local image uploads are saved as profile URLs, not a production media pipeline. Use shared contracts from `src/types` at module boundaries and import another module only through its public entry point.
